## 派发通道（Codex 桌面端实测，2026-09-21）

- **跨线程派发不吃提示词**：`create_thread` 传的 prompt 在子窗口只显示成一个气泡，子窗口模型实际收到空输入（实测两次，回「Ready.」和「Waiting on your request.」）；`send_message_to_thread` 同样进不了子窗口上下文。
- 因此开窗口只有两条路：① 由用户在窗口里手动发送一次（提示词已可见）；② 由统筹窗口起**子代理直接落在建好的 worktree 上**（路径 `git worktree list` 查），效果等同、全程不需要用户操作 —— 后续轮次按②走。

## 隔离（每个窗口一套，互不借用）

- 工作区：各自 `git worktree`（目录、`data/`、临时文件都分开）；只改自己 §5 行「改动范围」里的文件。
- 解释器：共用主仓库的 `.venv`（用绝对路径调用 `%USERPROFILE%\projects\Knowledge-Analysis-Assistant\.venv\Scripts\python.exe`）；`pip install` 必须串行。
- 密钥：`config/local.json` 是 gitignore 的，各 worktree 已各拷一份，别提交、别互相覆盖。
- 端口：按上表固定，谁也不占别人的端口；手工验证只连自己端口与自己的 `data/`。

## 热点文件规则（冲突只许出在这五个）

`backend/app/api/__init__.py`（路由汇总）、`backend/app/main.py`（装配）、`backend/app/services/registry.py`、`backend/app/services/tools.py`、`config/tools.json` 是每段都要碰的共享文件（F1 起的新路径，旧 `app/*.py` 读法作废）。

- 只**追加自己那一行/一段**，禁止重排顺序、改格式、动别人的行。
- 注册行加在各自区块末尾；新路由加在 API 路由块末尾、`StaticFiles` 挂载之前。
- 先合的占位，后合的重跑测试确认静态挂载仍在最后。

## 合并与收尾（只由主仓库窗口做，串行）

1. 分支窗口：本段验收 + 全量 `pytest tests -q` + `ruff check/format` 全绿 → 提交到自己的分支（**不推 main、不 force push**）。
2. 主仓库窗口一次只合一个分支：`git fetch` → `git merge --no-ff codex/<分支>` → 解冲突 → 重跑全量 + ruff → 更新 `docs/代码台账.md` → 提交并推送。
3. 谁后合谁解冲突、谁重跑测试；同一时间只允许一个分支处于合并/收尾中，其余窗口等通知。
4. 交接文档、台账、索引都是单文件就地改写，天然串行：一次只服务一个分支，别多窗口同写。

## 不能用并行的情况

- §5 依赖链上的相邻阶段（P8 → P9 → P10 → P11）：后一段依赖前一段的契约，只能串行。
- 需要改共享契约（签名、端点、表名、配置键）时：先回设计文档登记，再按上面的合并顺序走，别两个窗口同时改同一契约。
- **F2b 不能与 F1 并行**：它要改的 `backend/app/main.py`、`启动.cmd`、`tests/test_p5_flow.py` 正是 F1 重写的文件；F2a 之所以能并行，是因为它只新增 `frontend/**`（对 F1 零重叠）。
- **F6 不能与 F1 并行**：F6 往 `core/config.py`、`core/db.py`、`models/`、`alembic/` 里写，这些文件由 F1 创建。
