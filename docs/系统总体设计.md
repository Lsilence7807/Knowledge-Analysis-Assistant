- 每阶段结束时必须贴出验收命令的真实输出，不接受「应该没问题」。

## 1. 目标与非目标

目标：上传表格与文档 → 清洗入库 → 用中文多轮提问 → 由模型自主调用工具多步分析 → 给出带数字依据的结论、图表与可导出的报告；可挂 Skill、知识库、MCP 插件，可切换市面主流模型；同一份后端既能公网部署，也能打包成 Windows 安装包。

非目标（明确不做，做了算跑偏）：
- 模型微调 / LoRA / 蒸馏 / 自训练模型（数据量撑不起，换模型更划算）
- K8s、多租户 RBAC、合规审计体系
- 自建推理集群（vLLM、量化部署）；本地模型走 Ollama 即可
- 自研向量检索引擎与 embedding 模型（用现成 embedding 接口 + numpy 暴力检索）
- 自研 AI 网关、计费系统、模型训练平台
- 移动端适配；桌面端自动更新与代码签名
- 扫描件 OCR（需要 tesseract 时另立阶段）
- 对企业库的写操作与 DDL（数据源一律只读拉取）
- 自研 ETL 调度平台（同步只用最朴素的手动 + 定时触发）

## 2. 术语表

| 术语 | 含义 |
|---|---|
| dataset 数据集 | 一次上传的单个文件清洗后落成的 DuckDB 表，表名 `ds_<dataset_id>` |
| table_version | 数据版本号；重新导入或改清洗规则 +1，用于让缓存失效 |
| capability 能力 | 可插拔功能单元，注册在 registry，可关闭、可降级 |
| tool 工具 | 模型可调用的动作，带 JSON Schema 声明，注册在 tools 表 |
| agent step 步骤 | 一次工具调用及其观察结果，逐步记入 agent_steps |
| skill | 目录形式的技能包：`SKILL.md` + 可选 `scripts/` |
| metric 指标 | 语义层里的口径定义，含公式 SQL 与别名 |
| kb_doc 知识库文档 | 可检索的说明性文本，带向量 |
| model profile | 模型接入配置：id、provider 类型、base_url、模型名、密钥环境变量 |
| session 会话 | 一串多轮提问；记忆以它为单位 |
| turn 轮次 | 会话里的一次问答 |
| qa_cache 问答缓存 | 精确键 + 语义向量二级命中的历史答案 |
| trace span 调用链 | 一次模型/工具调用的耗时、token、成本记录 |
| eval run 评测轮次 | 对 golden set 跑一轮的结果与基线对比 |
| job 作业 | 耗时较长、转后台执行的任务 |
| degraded 降级 | 能力不可用时返回结构化说明，主链路仍成功 |
| source 数据源 | 外部数据库或文件的只读接入点，同步后落成 dataset |
| relation 关系 | 两张数据集之间的可 join 列对应，需登记确认后才允许 join |
| feedback 反馈 | 用户对某次结果的赞或踩，可提升为评测样例 |
| quota 配额 | 按日累计的 token 与成本上限 |

## 3. 总体架构

依赖单向，箭头由上到下；下层禁止 import 上层。

```

  ┌───────────────────────────────┬──────────────────────────────────────┐

  └───────────────┬───────────────┴──────────────┬───────────────────────┘
                  | HTTP / SSE                    | HTTP / SSE（本机回环）

app/models.py             模型 profile 注册表

                  |

                  |

                  |

+ data/files/（原始文件） + skills/ + config/ + evals/
```

一次追问的数据流：

1. `POST /sessions/{sid}/ask`（或 `GET /ask/stream` 走 SSE）
2. 认证 → 取数据集与 `table_version` → 精确缓存键
3. 命中且版本一致 → 直接返回历史 sql 与 insight，`cached: true`，不调模型
4. 未命中 → 语义缓存兜底（cosine ≥ 0.93 且版本一致 → 复用 SQL，结论重算）
5. 仍未命中 → `memory.context(sid)` + profile + 知识库召回片段 + 启用的 skill + 指标定义 → 交给 agent 循环
6. agent 逐步调用工具（run_sql / describe_stats / detect_anomalies / search_kb / run_code / call_mcp_tool…），每步记 agent_steps 与 trace_spans
7. 结果表 → `insight.summarize()` 生成结论 JSON → 写 turns 与 qa_cache（含向量）
8. 返回 `{sql, columns, rows, insight, steps, cached, reused_sql, degraded}`

### 4.5 LLM 契约

- 输入：profile + 指标定义 + 知识库召回片段（带出处）+ 启用的 skill + 最近 6 轮 question/sql + 最近 2 轮结论摘要 + 当前问题。
- 输出（Insight）：`summary, findings[], anomalies[], suggestions[], confidence(low|medium|high), caveats[]`。
- 硬规则：结论里的数字必须能在结果表中找到；证据不足写 `caveats`；指代不明返回 `need_clarify` 而不是猜。
- 失败处理：重试 1 次 → fallback 模型再试 1 次 → 仍失败则 `insight` 置空、`degraded` 追加 `insight:contract`，HTTP 仍 200。
- prompt 写成模块级常量并带 `PROMPT_VERSION`，缓存键要用它。

### 4.7 问答复用契约

- 精确路径：规范化（去空白 → 全角转半角 → 去标点 → 小写 → 合并空格）→ 键 = `sha256(dataset_id|table_version|model_id|PROMPT_VERSION|norm(question))` → 命中即返回历史 sql 与 insight，`cached: true`，零模型调用。
- 语义路径：未命中精确键时，对问题取 embedding 与同数据集同版本的历史问题比 cosine，≥ 0.93 命中 → **只复用 SQL 重新执行，insight 一律重算**，`reused_sql: true`。
- 失效条件：数据集重导入或清洗规则变更 → `table_version` +1 并 `invalidate()`；prompt 版本或模型变更 → 键自然不同。
- 禁止：数据版本不一致时复用结论；把复用结果标成新计算；缓存里存原始文件内容。

### 4.11 流式契约（P17）

- `GET /ask/stream?question=...&session_id=...` 返回 `text/event-stream`。
- 帧类型：`plan` → `sql` → `row_count` → `token`（可多次）→ `insight` → `trace` → `done`；任一步降级插 `degraded` 帧。
- 顺序保证：`sql` 一定早于任何 `token`；`done` 一定最后且唯一。
- 客户端断开：立即取消后续模型调用并记 `canceled`，不留后台僵尸请求。
- 非流式端点 `/ask`、`/sessions/{sid}/ask` 永久保留，`ENABLE_STREAM=false` 时前端自动回落。

### 4.12 数据源契约（P23，企业库位置留空）

`config/sources.json`（不放明文口令）：

- `type="enterprise"` 是**留空位**：接口、配置、端点、mock 测试齐备，但不绑定任何厂商驱动、不写方言适配。判定方式：`capabilities.sources.enterprise = false`，界面显示「未接入」。接哪家库、用什么驱动、方言怎么处理，留到真正对接时按四个函数填空。

### 4.13 多表关系契约（P22）

- `relations` 登记 `(left_dataset, left_col, right_dataset, right_col, kind, confidence, confirmed)`。
- 推断：列名同义匹配 + 类型一致 + 值交集采样（每表随机 1000 行）→ 置信度 0-1，≥ 0.8 自动登记为候选，其余只进 `/relations/suggest`。
- 硬规则：生成的 SQL 里出现的 join 必须命中已登记关系；未登记的 join 一律拒绝，回传「关系未确认」与候选清单。
- 理由：跨表分析是 NL2SQL 线上失败的第一大来源，把 join 条件从「模型猜」改成「查表」。

### 4.14 性能与并发契约（P21）

- 并发模型：所有阻塞工作（DuckDB 查询、pandas、模型 HTTP、子进程）必须经 `app/exec.py:run_blocking()` 调度，`exec_sql` 内部落实这条约定；路由层禁止直接调用阻塞函数。
- 默认 `EXEC_MAX_WORKERS=4`（DuckDB 与 pandas 是 CPU 密集，线程池够；换进程池要序列化结果，默认不做）。
- 目标基线（单机 4 核）：单表 50 万行聚合 p95 ≤ 1.5s；缓存命中 p95 ≤ 100ms；`/ask/stream` 首帧 ≤ 1.2s；10 并发无 5xx 且事件循环心跳延迟 p95 ≤ 200ms。
- 验证方式：`tests/test_p21_perf.py` 同时跑 asyncio 心跳与并发请求，断言心跳延迟与状态码；`bench/bench.py` 输出基线 JSON 存 `bench/baseline.json`，退化即失败。

### 4.15 反馈与配额契约（P24）

- `feedback` 表：`(task_id, verdict, reason, corrected_sql)`；`POST /feedback` 写入，前端在结论卡片上给赞/踩按钮。
- 提升：`POST /feedback/{id}/promote` 把一条 bad 反馈转成 golden 行追加到 `evals/golden.jsonl`（字段按第 4.10 节格式生成），同一问题重复提升只保留最新一条。
- 配额：按「主体 + 日」累计 token 与成本，达到 `QUOTA_DAILY_COST_USD` 即拒绝新的重分析请求并返回 429 + 说明；缓存命中不计入配额。
- 脱敏：反馈只存问题、SQL、结论摘要，不存原始数据行。
- 备注：`# ponytail: 配额记在 sqlite，多实例部署时移到共享存储`

## 6. 隔离机制

1. 依赖单向：只有 `main.py` 装配；`providers/*` 只被 `registry.py` 惰性 import；`nlu.py` / `agent.py` / `insight.py` 不认识 provider，只接收拼好的 context 或已注册的工具集。
2. 只增不改：每阶段允许改动的文件写死在「改动范围」；改契约必须在本文件登记并同步更新验收命令。
3. 独立超时与异常捕获：模型、工具、provider 任一失败 → 本次降级，HTTP 仍 200，`degraded` 指明能力与失败类别。
4. 进程与路径隔离：skill 脚本、MCP server、`run_code` 一律子进程，带超时，工作目录限制在项目内。
5. 能力开关：`ENABLE_SKILLS / ENABLE_KB / ENABLE_MCP / ENABLE_MEMORY / ENABLE_AGENT / ENABLE_SEMANTIC_CACHE / ENABLE_SANDBOX / ENABLE_STREAM / ENABLE_JOBS / ENABLE_AUTH / ENABLE_SOURCES / ENABLE_FEEDBACK / ENABLE_QUOTA`。新增能力默认关闭，出问题先关它再验证主链路是否干净。
6. 双壳同源：桌面端只打包同一份后端 + 打开本机回环，不复制业务代码、不开分支。

## 7. 安全边界

- SQL：单条 SELECT、拒 `;`、拒 DDL/DML、read_only、10s、5000 行
- 上传：后缀白名单（csv/xlsx/xls/pdf/docx）、大小上限 50MB、xlsx 走 `data_only=True`
- 代码沙箱：隔离子进程、临时目录、超时、输出上限、import 白名单、`python -I` 不继承环境；明确不是容器级隔离
- Agent：工具白名单；`write` 类工具需显式开启；步数与单步超时封顶；越权调用记录并拒绝
- Prompt injection：知识库片段、上传文档、MCP 返回内容一律视为不可信数据，进提示词前包裹标记并剥离指令性内容；文档内容不得触发工具调用或数据导出
- 认证：单密码 pbkdf2 + HMAC 签名 cookie（HttpOnly、SameSite=Lax、公网强制 Secure）；登录失败限流
- 数据归属：datasets 带 `owner`，所有读取路径校验
- 密钥：网页端存本机 `config/local.json`（页面写入，按 profile）或读环境变量；桌面端存 `%APPDATA%`；永不写入 exe、日志、SQL
- MCP：server 命令只来自 `config/mcp.json`，不接受请求参数；工具白名单；默认只读
- 日志：不打印文件内容与完整 prompt，只记长度、哈希、模型 id、耗时、成本

- 数据源：只读账号 + 只读拉取；连接串只经环境变量引用，不落任何文件与日志
- 企业库留空位不含凭据与样例数据，仓库里只有接口与 mock
- 反馈：只存问题、SQL 与结论摘要，不存原始数据行
- 配额：超限直接拒绝，不静默扣费

## 8. 关键决策（ADR）

- ADR-1 用 DuckDB 而不是 SQLite/Postgres：列存聚合快、能直接读 CSV、单文件零部署。
- ADR-2 不引 agent 框架：需要的是「工具调用循环」，自己写 100 行可控，框架会把 50 行变 500 行。
- ADR-3 模型调用集中：`app/llm.py` 唯一出口，业务代码不认识厂商。
- ADR-4 知识库先做 FTS5：P7 落地快，P14 再补向量，两条路并存互为降级。
- ADR-5 MCP 只做客户端：官方 SDK 的 stdio client，不自研协议。
- ADR-6 降级返回 200 而不是 5xx：能力缺失是产品状态，不是服务故障。
- ADR-7 一套后端两种壳：桌面端只打包 + 本机回环，复制第二份后端是最贵的错。
- ADR-8 只写 `openai_compatible` + `anthropic` 两个适配器：八成厂商提供兼容端点，新增厂商只改配置。
- ADR-9 缓存分级：精确键优先、语义兜底；复用结论的前提是数据没变，`table_version` 是这条规则的技术落点。
- ADR-10 exe 用 PyInstaller onedir + Inno Setup：onefile 冷启动慢、杀软误报多，体积换稳定。
- ADR-11 桌面端用用户自带密钥：密钥打进 exe 等于公开泄露。
- ADR-12 复用 SQL 可以，复用结论必须版本一致：结论数字必须对应当前数据。
- ADR-13 用工具调用取代自由文本 SQL：声明成工具让模型原生调用，参数可校验、可白名单、可记账；与 P3 的文本路径并存，单跳走便宜的那条。
- ADR-14 流式用 SSE 而不是 WebSocket：单向推送足够，FastAPI 原生支持，前端不引协议库。
- ADR-15 语义检索用现成 embedding 接口 + numpy 暴力检索，不引向量数据库：十万级数据量下省一个常驻服务（删掉了 chroma/sqlite-vec 的重方案）。
- ADR-16 沙箱用隔离子进程 + 超时，不上容器：单机自用够；公网多租户必须换容器级隔离。
- ADR-17 可观测自建 trace 表，不引 Langfuse：少一个外部依赖与密钥，够回答「花了多少钱、慢在哪」（删掉了 Langfuse 方案）。
- ADR-18 评测用 JSONL golden set + 基线对比，不引 eval 框架：pytest 能跑、结果进 git 就能防退化（删掉了 eval 框架方案）。
- ADR-19 后台作业用 BackgroundTasks + sqlite：单机单进程够用，多实例时换 Redis 队列。
- ADR-20 指标口径只在 `config/metrics.json` 定义：Skill 只写方法、引用 metric id，避免同一指标两套公式。

- ADR-21 企业库适配位留空：只定义四个函数的接口、配置与 mock 测试，不预装任何厂商驱动。留空的成本是一份文档和一个 Protocol，收益是接入时不改主链路。
- ADR-22 join 只走已登记关系：跨表失败主要来自模型猜 join，把条件从「生成」变成「查表」。
- ADR-23 阻塞工作统一走 `run_blocking`：FastAPI 里直接跑 pandas 或 DuckDB 会卡住事件循环，一个执行器解决，不许各写各的。
- ADR-24 反馈直接进评测集：用户点踩是最便宜的真实数据来源，进 golden set 才能防退化。
