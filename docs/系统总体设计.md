# AI 数据分析助手 · 系统总体设计 v3.1

唯一施工依据：一次只做一段，每段一条验收命令（§5），exit 0 才进下一段；任何阶段都不许弄坏已通过阶段的验收。§4 契约（HTTP API、响应形状、数据表）只追加不改签名；§4.2 的函数签名是**行为契约**，路径与实现一律按 §4.1 与 §11 走框架骨架。

**v3.1 骨架整改（2026-09-21）**：项目自身的骨架也不许手搭——后端按 FastAPI 官方模板的目录与依赖注入约定搭（`backend/app/{api,core,models,schemas,services}` + Alembic），前端换成 **React + Vite 骨架**（shadcn/ui 组件 + TanStack Query/Router + ECharts + assistant-ui 聊天壳（AI SDK runtime）），部署按 compose 多阶段镜像搭；AI 只写「血肉」（提示词、中文清洗规则、指标口径、业务组件、适配层）。**v3.0 框架化**继续有效：LiteLLM / LangGraph / LlamaIndex + LanceDB / SQLAlchemy + Alembic + pydantic-settings / sqlglot / RestrictedPython / itsdangerous + slowapi / sse-starlette / huey / Langfuse / deepeval + Ragas / Docling + docxtpl / dlt。已验收阶段的替换计划见 §5「F 段」，模块映射见 §11。版本历史：v1.0 P0-P8、v2.0 P9-P12、v2.1 P13-P20、v2.2 P21-P24、v3.0 框架化、v3.1 骨架整改。
## 1. 目标与非目标

目标：上传表格与文档 → 清洗入库 → 中文多轮提问 → 模型自主调工具多步分析 → 给出带数字依据的结论、图表与可导出报告；Skill、知识库、MCP 可挂，模型可换；同一份后端既能公网部署，也能打成 Windows 安装包。

非目标（做了算跑偏）：模型微调/LoRA/蒸馏；K8s、多租户 RBAC、合规审计；自建推理集群（本地模型走 Ollama）；自研向量引擎与 embedding；自研 AI 网关、计费与训练平台；移动端；扫描件 OCR；对企业库的写操作与 DDL；自研 ETL 调度平台。

## 2. 术语表

一行一个：dataset=一次上传清洗后落成的 DuckDB 表，表名 `ds_<dataset_id>`｜table_version=数据版本号，重导入或改清洗规则 +1，用于失效缓存｜capability=可插拔能力单元，注册在 registry，可关可降级｜tool=模型可调用的动作，带 JSON Schema，注册在 tools 表｜agent step=一次工具调用及观察，记入 agent_steps｜skill=目录技能包（`SKILL.md` + 可选 `scripts/`）｜metric=指标口径定义（公式 SQL + 别名）｜kb_doc=可检索说明文本，带向量｜model profile=模型接入配置（id / provider / base_url / 模型名 / 密钥环境变量）｜session 与 turn=会话与轮次，记忆以 session 为单位｜qa_cache=精确键 + 语义向量二级命中的历史答案｜trace span=一次模型或工具调用的耗时、token、成本｜eval run=对 golden set 跑一轮并与基线对比｜job=耗时较长、转后台执行的任务｜degraded=能力不可用时返回结构化说明，主链路仍成功｜source=外部数据库或文件的只读接入点，同步后落成 dataset｜relation=两个数据集之间已确认的可 join 列对应｜feedback=用户对某次结果的赞或踩，可提升为评测样例｜quota=按日累计的 token 与成本上限。

## 3. 总体架构

依赖单向，下层禁止 import 上层；文件路径全清单见 §4.1（换框架不改路径），每个模块背后的框架见 §11。总原则：**自研代码只留编排、契约与项目特有逻辑，能用框架的一律用框架**。

分层（自上而下）：`frontend/`（React 应用，构建产物 `web/dist`） → **FastAPI** `backend/app/main.py`（`create_app()` 装配点，端点分散在 `api/routes/*`）→ 编排层 `services/agent.py`（**LangGraph** 图 + checkpointer 记忆 + `astream_events` 流式）/ `services/tools.py`（**LangChain `@tool`** 注册表）/ `services/registry.py`（能力开关）/ `services/trace.py`（**Langfuse**）→ 能力层 `services/insight.py` 与 `services/nlu.py`（**LangChain prompt + LiteLLM 结构化输出**）/ `services/cache.py`（**LiteLLM cache** + LanceDB 向量）/ `services/sandbox.py`（**RestrictedPython** + 隔离子进程）/ `services/metrics.py` / `services/report.py`（**docxtpl** + python-pptx）/ `services/evalharness.py`（**deepeval / Ragas**）/ `providers/*`（`kb.py` = **LlamaIndex + LanceDB**；`mcp_client.py` = 官方 SDK + **langchain-mcp-adapters**；`sources.py` = **dlt + SQLAlchemy**）→ 数据层 `core/db.py`（**sqlglot** 守卫 + DuckDB 只读连接）/ `models/*` + `alembic/`（**SQLAlchemy 2.0 + Alembic**）/ `services/ingest.py`（pandas + **pandera** + **ydata-profiling**）/ `core/exec.py`（**starlette `run_in_threadpool`**）→ DuckDB（分析数据）+ SQLite（元数据/会话/缓存/调用链/作业）+ `data/files/` + `skills/` + `config/` + `evals/`。

模型调用只有一个出口：**LiteLLM**——`services/llm.py` 是它的薄封装，`config/models.json` 只当配置（启动时生成 Router 的 deployment 列表与 fallback 链），业务代码不认识厂商。

一次追问的数据流：`POST /sessions/{sid}/ask`（或 `GET /ask/stream` 走 **sse-starlette**）→ 认证（**itsdangerous** 签名 cookie）→ 取数据集与 `table_version` → **LiteLLM cache** 精确键命中即返回历史 sql 与 insight（零模型调用）→ 未命中走语义缓存兜底（向量在 LanceDB，只复用 SQL、结论重算）→ 仍未命中则 checkpointer 取会话状态 + LiteLLM 按 `purpose` 选模型 + LlamaIndex 召回知识库片段（带出处）+ 启用的 skill + 指标定义 → 交 **LangGraph** 图逐步调工具（每个节点 = 一步，节点回调同时写 `agent_steps` 与 Langfuse）→ 结果表经 `insight.summarize()`（结构化输出）出结论 → 写 turns 与 qa_cache → 返回 `{sql, columns, rows, insight, steps, cached, reused_sql, degraded}`。

**实现方（v3.0：签名不变，只换背后的框架）**：`llm.py` = LiteLLM Router 薄封装（结构化输出、回退、重试、embedding、成本一次给全）；`services/llm_models.py`（原 `app/models.py`）= 由 `config/models.json` 生成 LiteLLM deployment 列表；`agent.py` = LangGraph 图（`recursion_limit` 即 `max_steps`）；`memory.py` = 读 LangGraph checkpointer 的状态历史，只做格式化；`cache.py` = LiteLLM cache + LanceDB 向量；`tools.py` = LangChain `@tool`（pydantic 入参自动出 JSON Schema）；`store.py` = SQLAlchemy 2.0（表结构见 §4.4 不变，建表与变更走 Alembic）；`config.py` = pydantic-settings；`db.py` = sqlglot 校验 + DuckDB 只读连接；`sandbox.py` = RestrictedPython 守卫 + 隔离子进程；`stream.py` = sse-starlette；`exec.py` = 保留自研 `ThreadPoolExecutor`（无框架对应物：anyio/starlette 线程门户在本机沙箱挂住，见 §11）；`trace.py` = Langfuse；`evalharness.py` = deepeval / Ragas；`report.py` = docxtpl / python-pptx；`jobs.py` = huey；`providers/kb.py` = LlamaIndex + LanceDB；`providers/docs.py` = Docling / MarkItDown；`providers/sources.py` = dlt + SQLAlchemy；`auth.py` = itsdangerous + slowapi。**返回形状与验收命令一律不变**；函数签名要动仍按 §6「改契约先登记」。

**路径与分层（v3.1）**：本节签名一律读作 `backend/app/...`。`api/deps.py` 提供 `Depends` 依赖（`get_settings` / `get_session` / `get_current_user` / `require_capability(name)` / `get_dataset`）；路由函数只声明依赖，不自己取全局状态；`services/*` 是可被路由与其他 service 调用的业务模块（不认识 FastAPI）；`schemas/*` 是唯一允许出现在路由签名里的类型。新增端点 = `api/routes/` 加文件 + `api/__init__.py` 加一行（§6 规则 8），不再往 `main.py` 里塞。

### 4.5 LLM 契约

- 输入：profile + 指标定义 + 知识库召回片段（带出处）+ 启用的 skill + 最近 6 轮 question/sql + 最近 2 轮结论摘要 + 当前问题。
- 输出（Insight）：`summary, findings[], anomalies[], suggestions[], confidence(low|medium|high), caveats[]`；`findings[]` 每条带 `row`（结果表 0 基行号，K-009）与可选 `column`。
- 硬规则：结论里的数字必须能在结果表中找到，或出自 findings 指认的那些行（合计、比率、环比这类算式结果按引用追溯）；findings 没指认来源时按字面比对，标识符（表名 `ds_<id>`、列名）里的数字不算（K-018）；证据不足写 `caveats`；指代不明返回 `need_clarify` 而不是猜。
- 失败处理：重试 1 次 → fallback 模型再试 1 次 → 仍失败则 `insight` 置空、`degraded` 追加 `insight:contract`（模型不可用或调用失败是 `insight:llm`），HTTP 仍 200。
- prompt 写成模块级常量并带 `PROMPT_VERSION`，缓存键要用它。

- 实现（v3.0）：输出契约直接写成 pydantic 模型交给 **LiteLLM `response_format`**（内部走厂商结构化输出或函数调用），不再手写 JSON 解析与修复；重试与换模型交给 LiteLLM 的 `num_retries` + `fallbacks`，`insight.py` 只负责判空与降级；prompt 用 **LangChain `ChatPromptTemplate`**，`PROMPT_VERSION` 仍写在模块级常量里（缓存键要用它）。

### 4.7 问答复用契约

- 精确路径：规范化（去空白 → 全角转半角 → 去标点 → 小写 → 合并空格）→ 键 = `sha256(dataset_id|table_version|model_id|PROMPT_VERSION|norm(question))` → 命中即返回历史 sql 与 insight，`cached: true`，零模型调用。
- 语义路径：未命中精确键时，对问题取 embedding 与同数据集同版本的历史问题比 cosine，≥ 0.93 命中 → **只复用 SQL 重新执行，insight 一律重算**，`reused_sql: true`。
- 失效条件：数据集重导入或清洗规则变更 → `table_version` +1 并 `invalidate()`；prompt 版本或模型变更 → 键自然不同。
- 禁止：数据版本不一致时复用结论；把复用结果标成新计算；缓存里存原始文件内容。

### 4.11 流式契约（P17）

- `GET /ask/stream?question=...&session_id=...` 返回 `text/event-stream`。
- 帧类型：`plan` → `sql` → `row_count` → `token`（可多次）→ `insight` → `trace` → `done`；任一步降级插 `degraded` 帧。
- 顺序保证：`sql` 一定早于任何 `token`；`done` 一定最后且唯一。
- 载荷：`row_count` 带 `columns` 与 `rows`（前端只有这一条流，表格与图表都靠它）；`degraded` 带 `{stage, reason, message?}`；`trace` 带 `{task_id, steps, elapsed_ms}`；`insight` 带 `{insight, text, message}`；`done` 带 `{task_id, degraded, message, elapsed_ms}`。
- 客户端断开：立即取消后续模型调用并记 `canceled`，不留后台僵尸请求。
- 非流式端点 `/ask`、`/sessions/{sid}/ask` 永久保留，`ENABLE_STREAM=false` 时前端自动回落。

### 4.13 多表关系契约（P22）

- `relations` 登记 `(left_dataset, left_col, right_dataset, right_col, kind, confidence, confirmed)`。
- 推断：列名同义匹配 + 类型一致 + 值交集采样（每表随机 1000 行）→ 置信度 0-1，≥ 0.8 自动登记为候选，其余只进 `/relations/suggest`。
- 硬规则：生成的 SQL 里出现的 join 必须命中已登记关系；未登记的 join 一律拒绝，回传「关系未确认」与候选清单。

### 4.14 性能与并发契约（P21）

- 并发模型：所有阻塞工作（DuckDB 查询、pandas、模型 HTTP、子进程）必须经 `app/exec.py:run_blocking()` 调度，`exec_sql` 内部落实这条约定；路由层禁止直接调用阻塞函数。
- 默认 `EXEC_MAX_WORKERS=4`（DuckDB 与 pandas 是 CPU 密集，线程池够；换进程池要序列化结果，默认不做）。
- 目标基线（单机 4 核）：单表 50 万行聚合 p95 ≤ 1.5s；缓存命中 p95 ≤ 100ms；`/ask/stream` 首帧 ≤ 1.2s；10 并发无 5xx 且事件循环心跳延迟 p95 ≤ 200ms。
- 验证方式：`tests/test_p21_perf.py` 同时跑 asyncio 心跳与并发请求，断言心跳延迟与状态码；`bench/bench.py` 输出基线 JSON 存 `bench/baseline.json`，退化即失败。

### 4.15 反馈与配额契约（P24）

- `feedback` 表：`(task_id, verdict, reason, corrected_sql)`；`POST /feedback` 写入，前端在结论卡片上给赞/踩按钮。

- 脱敏：反馈只存问题、SQL、结论摘要，不存原始数据行。

## 6. 隔离机制

1. 依赖单向：只有 `main.py` 装配；`providers/*` 只被 `registry.py` 惰性 import；`nlu.py` / `agent.py` / `insight.py` 不认识 provider，只接收拼好的 context 或已注册的工具集。
2. 只增不改：每阶段允许改的文件写死在 §5 的「改动范围」；改契约必须在本文件登记并同步更新验收命令。
3. 独立超时与异常捕获：模型、工具、provider 任一失败 → 本次降级，HTTP 仍 200，`degraded` 指明能力与失败类别。
4. 进程与路径隔离：skill 脚本、MCP server、`run_code` 一律子进程，带超时，工作目录限制在项目内。
5. 能力开关（新增能力默认关闭，出问题先关它再验证主链路是否干净）：`ENABLE_SKILLS / ENABLE_KB / ENABLE_MCP / ENABLE_MEMORY / ENABLE_AGENT / ENABLE_SEMANTIC_CACHE / ENABLE_SANDBOX / ENABLE_STREAM / ENABLE_JOBS / ENABLE_AUTH / ENABLE_SOURCES / ENABLE_FEEDBACK / ENABLE_QUOTA`（全部默认 false；唯一例外是 `ENABLE_AGENT`，默认 true，见 §10）。
6. （已作废 2026-09-21：桌面端移出范围，只做网页端；编号保留，免得打乱下文引用。）
7. 框架优先（v3.0）：能用现成框架的一律不自己写；新增模块先查 §11 的表，表里有就用表里的。自研等价物只有「框架解决不了」一种合法理由，且理由要写进 §8。
8. 骨架不许手搭（v3.1）：新增页面走 `frontend/src/routes` 的模板约定，新增端点走 `api/routes` + `api/__init__.py`，建表走 Alembic 迁移，组件先查 shadcn/ui 有没有；都不许另起一套写法。

## 7. 安全边界

- SQL：单条 SELECT、拒 `;`、拒 DDL/DML、read_only、10s、5000 行。
- 上传：后缀白名单（最终 csv/xlsx/xls/pdf/docx；F9 起 pdf/docx 已进白名单，正文抽取走 `providers/docs.py`）、50MB 上限、xlsx 走 `data_only=True`。
- 代码沙箱：隔离子进程、临时目录、超时、输出上限、import 白名单、`python -I` 不继承环境；明确不是容器级隔离。
- Agent：工具白名单；`write` 类工具需显式开启；步数与单步超时封顶；越权调用记录并拒绝。
- Prompt injection：知识库片段、上传文档、MCP 返回内容一律视为不可信数据，进提示词前包裹标记并剥离指令性内容；文档内容不得触发工具调用或数据导出。
- 认证：单密码 pbkdf2 + HMAC 签名 cookie（HttpOnly、SameSite=Lax、公网强制 Secure）；登录失败限流。
- 数据归属：datasets 带 `owner`，所有读取路径校验。
- 密钥：网页端存本机 `config/local.json`（页面写入、按 profile）或读环境变量；永不写入日志、SQL、镜像与任何交付产物。
- MCP：server 命令只来自 `config/mcp.json`，不接受请求参数；工具白名单；默认只读。
- 日志：不打印文件内容与完整 prompt，只记长度、哈希、模型 id、耗时、成本。
- 数据源：只读账号 + 只读拉取；连接串只经 `dsn_env` 引用环境变量，不落文件与日志；企业库留空位不含凭据与样例数据。
- 反馈：只存问题、SQL 与结论摘要，不存原始数据行。配额：超限直接拒绝，不静默扣费。

**v3.0 落点（规则不变，只换实现）**：
- SQL 守卫 → **sqlglot** 解析成语法树后判「单条 SELECT、无 DDL/DML、无多语句」，DuckDB 连接强制只读；正则只留作解析失败时的兜底。
- 沙箱 → **RestrictedPython** 编译期守卫（替换手写 AST 检查）+ 现有隔离子进程兜底（临时目录、超时、输出上限不变）；公网多租户升级成 Docker 隔离或云沙箱，注意 `e2b` 这类云沙箱会把数据送出本机，企业数据默认不开。
- Prompt injection → 统一挂 **LiteLLM guardrail hooks**（知识库片段、上传文档、MCP 返回、技能正文都过一遍），可选叠加 **LLM Guard** 本地扫描与 **Presidio** 脱敏；包裹标记与行级剥离逻辑保留。**实现落点：`backend/app/core/guardrail.py`**（kb / MCP / 技能正文统一过 `guard`，命中记 `capability_log` 并按上文口径拒绝；挂载点是 LiteLLM `async_moderation_hook`，`llm.py` import 时幂等装一次）。
- 认证 → **itsdangerous** `URLSafeTimedSerializer` 签 cookie + **slowapi** 限流（替换手写 HMAC 与计数器），单密码校验仍用 stdlib `pbkdf2_hmac`。
- 密钥 → **pydantic-settings** 统一取值（env → `config/local.json` → profile 的 `api_key_env`），密钥永不进日志、报错、SQL。
- 数据源 → **dlt** 只读 pipeline + 只读账号；连接串仍只经 `dsn_env` 引用环境变量。

## 8. 关键决策（ADR，防止重复讨论同一件事）

- ADR-1 用 DuckDB 而非 SQLite/Postgres：列存聚合快、可直接读 CSV、单文件零部署。
- ADR-2 不引 agent 框架：自写工具调用循环约 100 行，框架会把 50 行变 500 行。
- ADR-3 模型调用集中：`app/llm.py` 唯一出口，业务代码不认识厂商。
- ADR-4 知识库先 FTS5（P7 快），P14 再补向量，两条路并存互为降级。**2026-09-20 落地口径**：FTS5 建在 SQLite 的 `kb_fts`（标准库自带、离线可用；`trigram` 分词才搜得到连续中文，实测 `unicode61` 不行），DuckDB 只管数据集表——它的 `fts` 扩展要联网 `INSTALL`，离线会挂。
- ADR-5 MCP 只做客户端（官方 stdio SDK），不自研协议。
- ADR-6 降级返回 200 而不是 5xx：能力缺失是产品状态，不是服务故障。
- ADR-7 **（已作废 2026-09-21：桌面端移出范围）** 一套后端两种壳：桌面端只打包 + 回环；复制第二份后端是最贵的错。
- ADR-8 只写 `openai_compatible` + `anthropic` 两个适配器：多数厂商给兼容端点，新增厂商只改配置。
- ADR-9 缓存分级：精确键优先、语义兜底；复用结论的前提是数据没变，`table_version` 是这条规则的落点。
- ADR-10 exe 用 PyInstaller onedir + Inno Setup：onefile 冷启动慢、杀软误报多。
- ADR-11 **（已作废 2026-09-21：桌面端移出范围）** 用用户自带密钥，密钥绝不内嵌进交付产物。
- ADR-12 复用 SQL 可以，复用结论必须版本一致：结论数字必须对应当前数据。
- ADR-13 用工具调用取代自由文本 SQL：可校验、可白名单、可记账；与 P3 文本路径并存，单跳走便宜那条。
- ADR-14 流式用 SSE 而不是 WebSocket：单向推送足够，FastAPI 原生支持。
- ADR-15 语义检索用现成 embedding 接口 + numpy 暴力检索，不引向量数据库（十万级够用）。
- ADR-16 沙箱用隔离子进程 + 超时，不上容器：单机自用够，公网多租户必须换容器级隔离。
- ADR-17 可观测自建 trace 表，不引 Langfuse：少一个外部依赖，够回答「花了多少钱、慢在哪」。
- ADR-18 评测用 JSONL golden set + 基线对比，不引 eval 框架：pytest 能跑、结果进 git 就能防退化。
- ADR-19 后台作业用 BackgroundTasks + sqlite：单机单进程够用，多实例换 Redis 队列。
- ADR-20 指标口径只在 `config/metrics.json` 定义：Skill 只写方法、引用 metric id，避免同一指标两套公式。
- ADR-21 企业库适配位留空：只定义四个函数的接口、配置与 mock 测试，不预装厂商驱动；成本是一份文档和一个 Protocol，收益是接入时不改主链路。
- ADR-22 join 只走已登记关系：把 join 条件从「模型生成」变成「查表」。
- ADR-23 阻塞工作统一走 `run_blocking`：FastAPI 里直接跑 pandas 或 DuckDB 会卡住事件循环，不许各写各的。
- ADR-24 反馈直接进评测集：用户点踩是最便宜的真实数据来源。

**v3.0 废止（被框架取代，别再按旧结论讨论）**：
- ADR-2（不引 agent 框架）**废止** → 改用 **LangGraph**：手写循环单看起点小，加「会话状态、流式、子图、断点续跑、人在环」时膨胀最快。
- ADR-8（只写两个适配器）**废止** → **LiteLLM** 覆盖全部厂商、路由与回退。
- ADR-15（numpy 暴力检索，不引向量库）**废止** → **LlamaIndex + LanceDB**（内嵌，免起服务）。
- ADR-17（自建 trace 表，不引 Langfuse）**废止** → **Langfuse**（本地表仍留作 `/trace/stats` 的降级读取）。
- ADR-18（不引 eval 框架）**废止** → **deepeval + Ragas**（基线对比仍 exit 1）。
- ADR-19（BackgroundTasks + sqlite）**废止** → **huey**（sqlite 存储，仍然单机免 Redis）。
- ADR-23（自研 `run_blocking`）**废止** → `starlette.concurrency.run_in_threadpool`（原生，语义一致）。
- 仍然有效：ADR-1（DuckDB）、ADR-3（模型调用集中，出口现在是 LiteLLM）、ADR-4（FTS5 关键词路径保留为降级）、ADR-5（MCP 只做客户端）、ADR-6（降级返回 200；ADR-7 双壳同源已作废）、ADR-9 / ADR-12（缓存分级、结论必须版本一致）、ADR-13 / ADR-14（工具调用取代自由文本 SQL、流式用 SSE）、ADR-16 的本地口径（单机不上容器）、ADR-20（指标口径仍只在 `config/metrics.json` 定义）、ADR-21（企业库位置留空）、ADR-22（join 只走已登记关系）、ADR-24（反馈进评测集）。

**v3.0 新增**：
- ADR-25 框架优先（总纲）：能用现成框架的一律不自己写。新增模块先查 §11；表里有就用表里的。自研等价物只有一种合法理由——框架解决不了，且这个理由要写进本节。
- ADR-26 模型层用 LiteLLM：一个依赖解决多厂商、路由、回退、重试、结构化输出、embedding、成本与缓存，`llm.py` 退化成薄封装。
- ADR-27 Agent 与记忆用 LangGraph：图 + checkpointer 一次拿到循环、状态持久化与流式事件，每步轨迹天然对应 `agent_steps`。
- ADR-28 检索用 LlamaIndex + LanceDB：分块、索引、召回、rerank 都在框架里，FTS5 保留为降级。
- ADR-29 SQL 守卫用 sqlglot：解析真语法树比正则可靠，还能直接判方言与 join 合法性。
- ADR-30 数据层用 SQLAlchemy + Alembic + pydantic-settings：表会变就得有迁移，配置要有校验，两件都不值得手写。
- ADR-31 沙箱用 RestrictedPython + 隔离子进程：编译期守卫替换手写 AST 检查；「不是容器隔离」这条不变。
- ADR-32 认证用 itsdangerous + slowapi：签名 cookie 与限流都是被广泛审计过的现成件。
- ADR-33 作业队列用 huey（sqlite 后端）：单机免 Redis 仍能拿到重试、定时与持久化；多实例换 arq + Redis。
- ADR-34 观测用 Langfuse、评测用 deepeval + Ragas：耗时、token、成本、检索质量一次到位，本地表只做降级。
- ADR-35 文档解析用 Docling（重）/ MarkItDown（轻），导出用 docxtpl + python-pptx + Jinja2。
- ADR-36 数据源同步用 dlt：只读抽数、增量水位、落表都是它的本职，适配器只剩配置。
- ADR-37（**v3.1 废止**）前端可选 Chainlit：已被 ADR-40 的 React 骨架取代，不再考虑；原「默认保留自研单页」的口径一并作废。
- ADR-38 用依赖体积换开发速度：框架会撑大依赖树与镜像体积（预估 +200~400MB）并增加版本冲突面，接受；代价控制手段是 `FRAMEWORK_PROFILE=core` 与镜像多阶段裁剪，而不是回退自研。

**v3.1 骨架（ADR-39~43）**：
- ADR-39 后端骨架借 `fastapi/full-stack-fastapi-template` 的目录与依赖注入，不借它的栈（不换 SQLModel、不引 JWT/Playwright）：换来的是「路由 / 依赖 / 服务 / 模型 / 迁移各归其位」这套被大量项目验证过的骨架，代价是一次整包搬路径。
- ADR-40 前端换 React + Vite + TS + Tailwind + shadcn/ui 骨架，聊天壳、流式与工具调用接 `assistant-ui`（底层 AI SDK runtime）的现成组件，图表用 `echarts-for-react` 复用现有 ECharts 配置；代价是引入 Node 构建链，`启动.cmd` 多一步「缺 dist 则构建」。
- ADR-41 测试与配置根不搬（`tests/`、`config/`、`data/`、`skills/`、`evals/` 留仓库根）：验收命令与 CI 口径保持不变，骨架换新不动验收。
- ADR-42 前端 API 客户端由后端 `/openapi.json` 生成（`openapi-typescript`）：契约改了前端类型自动跟着变，**禁止手写第二份接口定义**。
- ADR-43 构建产物不进仓库（`web/dist` gitignore），但离线交付必须包含它：CI 构建、`启动.cmd` 按需构建、镜像由 node 阶段产出。
