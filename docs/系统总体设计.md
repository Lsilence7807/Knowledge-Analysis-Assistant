# AI 数据分析助手 · 系统总体设计 v2.2

唯一施工依据：一次只做一段，每段一条验收命令（§5），exit 0 才进下一段；任何阶段都不许弄坏已通过阶段的验收。§4 契约只追加不改签名；扩展只允许「新建文件 + 注册表加一行 + 编排层插调用」（§6）。版本历史：v1.0 P0-P8、v2.0 加 P9-P12、v2.1 加 P13-P20、v2.2 加 P21-P24。

## 1. 目标与非目标

目标：上传表格与文档 → 清洗入库 → 中文多轮提问 → 模型自主调工具多步分析 → 给出带数字依据的结论、图表与可导出报告；Skill、知识库、MCP 可挂，模型可换；同一份后端既能公网部署，也能打成 Windows 安装包。

非目标（做了算跑偏）：模型微调/LoRA/蒸馏；K8s、多租户 RBAC、合规审计；自建推理集群（本地模型走 Ollama）；自研向量引擎与 embedding；自研 AI 网关、计费与训练平台；移动端、桌面端自动更新与代码签名；扫描件 OCR；对企业库的写操作与 DDL；自研 ETL 调度平台。

## 2. 术语表

一行一个：dataset=一次上传清洗后落成的 DuckDB 表，表名 `ds_<dataset_id>`｜table_version=数据版本号，重导入或改清洗规则 +1，用于失效缓存｜capability=可插拔能力单元，注册在 registry，可关可降级｜tool=模型可调用的动作，带 JSON Schema，注册在 tools 表｜agent step=一次工具调用及观察，记入 agent_steps｜skill=目录技能包（`SKILL.md` + 可选 `scripts/`）｜metric=指标口径定义（公式 SQL + 别名）｜kb_doc=可检索说明文本，带向量｜model profile=模型接入配置（id / provider / base_url / 模型名 / 密钥环境变量）｜session 与 turn=会话与轮次，记忆以 session 为单位｜qa_cache=精确键 + 语义向量二级命中的历史答案｜trace span=一次模型或工具调用的耗时、token、成本｜eval run=对 golden set 跑一轮并与基线对比｜job=耗时较长、转后台执行的任务｜degraded=能力不可用时返回结构化说明，主链路仍成功｜source=外部数据库或文件的只读接入点，同步后落成 dataset｜relation=两个数据集之间已确认的可 join 列对应｜feedback=用户对某次结果的赞或踩，可提升为评测样例｜quota=按日累计的 token 与成本上限。

## 3. 总体架构

依赖单向，下层禁止 import 上层；文件路径全清单见 §4.1。

分层（自上而下）：`web/index.html`（浏览器）或 `desktop/`（打包 exe，仅本机回环）→ `main.py`（路由：校验 + 编排 + 认证，唯一装配点）→ `auth / stream / jobs / agent / tools / llm / models / registry / trace` → `nlu / insight / memory / sandbox / metrics / report / evalharness / providers/*` → `db / store / ingest / cache / exec` → DuckDB（分析数据）+ SQLite（元数据/会话/缓存/调用链/作业）+ `data/files/` + `skills/` + `config/` + `evals/`。

一次追问的数据流：`POST /sessions/{sid}/ask`（或 `GET /ask/stream` 走 SSE）→ 认证 → 取数据集与 `table_version` → 算精确缓存键 → 命中且版本一致则直接返回历史 sql 与 insight（`cached: true`，零模型调用）→ 未命中走语义缓存兜底（cosine ≥ 0.93，只复用 SQL，结论重算）→ 仍未命中则 `memory.context(sid)` + model profile + 知识库召回片段 + 启用的 skill + 指标定义 → 交给 agent 循环逐步调工具（每步记 agent_steps 与 trace_spans）→ 结果表经 `insight.summarize()` 出结论 → 写 turns 与 qa_cache → 返回 `{sql, columns, rows, insight, steps, cached, reused_sql, degraded}`。

### 4.5 LLM 契约

- 输入：profile + 指标定义 + 知识库召回片段（带出处）+ 启用的 skill + 最近 6 轮 question/sql + 最近 2 轮结论摘要 + 当前问题。
- 输出（Insight）：`summary, findings[], anomalies[], suggestions[], confidence(low|medium|high), caveats[]`；`findings[]` 每条带 `row`（结果表 0 基行号，K-009）与可选 `column`。
- 硬规则：结论里的数字必须能在结果表中找到，或出自 findings 指认的那些行（合计、比率、环比这类算式结果按引用追溯）；findings 没指认来源时按字面比对，标识符（表名 `ds_<id>`、列名）里的数字不算（K-018）；证据不足写 `caveats`；指代不明返回 `need_clarify` 而不是猜。
- 失败处理：重试 1 次 → fallback 模型再试 1 次 → 仍失败则 `insight` 置空、`degraded` 追加 `insight:contract`（模型不可用或调用失败是 `insight:llm`），HTTP 仍 200。
- prompt 写成模块级常量并带 `PROMPT_VERSION`，缓存键要用它。

- `purpose` 允许 SQL 用小模型、结论用强模型。
- 密钥来源：页面写入的本机文件优先、环境变量兜底，**按 profile 存**（页面可配任意 OpenAI 兼容厂商的 base_url / 模型名 / 密钥，写进 `config/local.json` 的 `models` + `api_keys`；环境变量名由该 profile 的 `api_key_env` 声明，最后兜底通用 `LLM_API_KEY`）；桌面端从 `%APPDATA%\Knowledge-Analysis-Assistant\config.json` 读，绝不内嵌进 exe。

### 4.7 问答复用契约

- 精确路径：规范化（去空白 → 全角转半角 → 去标点 → 小写 → 合并空格）→ 键 = `sha256(dataset_id|table_version|model_id|PROMPT_VERSION|norm(question))` → 命中即返回历史 sql 与 insight，`cached: true`，零模型调用。
- 语义路径：未命中精确键时，对问题取 embedding 与同数据集同版本的历史问题比 cosine，≥ 0.93 命中 → **只复用 SQL 重新执行，insight 一律重算**，`reused_sql: true`。
- 失效条件：数据集重导入或清洗规则变更 → `table_version` +1 并 `invalidate()`；prompt 版本或模型变更 → 键自然不同。
- 禁止：数据版本不一致时复用结论；把复用结果标成新计算；缓存里存原始文件内容。

### 4.8 工具契约（P13）

`config/tools.json` 控制白名单、超时与步数预算。

| 工具 | kind | 作用 | 引入 |
|---|---|---|---|
| run_sql | read | 执行单条 SELECT（最多 5000 行） | P13 |
| describe_stats | read | 描述统计 | P13 |
| detect_anomalies | read | IQR/z-score 异常 | P13 |
| search_kb | read | 知识库召回 | P7 |
| list_skills / use_skill | read | 技能列表 / 取提示词片段 | P6 |
| call_mcp_tool | read | 调用白名单内 MCP 工具 | P8 |
| list_metrics | read | 指标口径 | P15 |
| run_code | read | 受限沙箱执行 pandas 代码 | P15 |
| export_report | write | 导出报告 | P19 |

硬规则：默认 `max_steps=6`；每步独立超时；每步取数与 `/query` 同口径（最多 5000 行，末步响应表不再被截到 200 行，K-008）；回给模型的结果超过 200 行只回列名与行数（全表留在服务端，下一步用 `run_sql` 再取）；`write` 类工具必须显式开关；越权调用记 `capability_log` 并返回拒绝说明；步数耗尽时返回已完成步骤与结论说明，不报错。**K-023 补丁**：白名单校验落在 `tools.call()` 内部，不只靠 agent 那层——任何入口直调白名单外的工具都抛 `ToolError` 并记一行 `capability_log(capability=tools, event=error)`；`call` 签名不变。

### 4.9 指标语义层契约（P15）

`config/metrics.json`：

```json
{"id": "sales_amount", "name": "销售额", "aliases": ["销售额", "营收", "GMV"],
 "formula_sql": "sum(amount)", "unit": "元", "owner": "运营", "note": "不含退货"}
```

- 规则：提问里出现的指标名必须先解析成指标 id；未定义的指标名不允许臆造公式，改为反问或标注「口径未定义」。
- 冲突消解：Skill 只描述分析方法，口径一律引用 metric id，禁止在 Skill 里另写一套公式。

### 4.10 评测契约（P16）

`evals/golden.jsonl` 每行：

```json
{"id": "q001", "fixture": "sales_2025.csv", "question": "上月华东区销售额环比下降的产品有哪些",
 "expect_sql_contains": ["group by", "sum(amount)"], "expect_columns": ["product", "ratio"],
 "expect_insight_fields": ["summary", "suggestions"], "forbid_phrases": ["无法确定", "可能"]}
```

- 指标：`sql_pass_rate ≥ 0.80`、`fidelity_rate ≥ 0.95`（结论数字可在结果表中回溯）、`degrade_rate ≤ 0.05`、记录 `cost_per_task`。
- 命令：`python -m app.evalharness --golden evals/golden.jsonl --baseline evals/baseline.json`；低于基线即 exit 1。

### 4.11 流式契约（P17）

- `GET /ask/stream?question=...&session_id=...` 返回 `text/event-stream`。
- 帧类型：`plan` → `sql` → `row_count` → `token`（可多次）→ `insight` → `trace` → `done`；任一步降级插 `degraded` 帧。
- 顺序保证：`sql` 一定早于任何 `token`；`done` 一定最后且唯一。
- 客户端断开：立即取消后续模型调用并记 `canceled`，不留后台僵尸请求。
- 非流式端点 `/ask`、`/sessions/{sid}/ask` 永久保留，`ENABLE_STREAM=false` 时前端自动回落。

### 4.12 数据源契约（P23，企业库位置留空）

`config/sources.json`（不放明文口令）：

```json
{
  "sources": [
    {"id": "demo_sqlite", "type": "sqlite", "dsn_env": "DEMO_SQLITE_DSN", "readonly": true, "tables": ["orders"]},
    {"id": "erp_mysql", "type": "enterprise", "dsn_env": "ERP_DSN", "readonly": true,
     "tables": [], "watermark_column": "updated_at", "placeholder": true}
  ]
}
```

- 适配器接口见第 4.2 节 `SourceAdapter`：接入企业库只需补一个模块实现那四个函数并注册进 `ADAPTERS`，其余代码一行不动。
- `type="enterprise"` 是**留空位**：接口、配置、端点、mock 测试齐备，但不绑定任何厂商驱动、不写方言适配。判定方式：`capabilities.sources.enterprise = false`，界面显示「未接入」。接哪家库、用什么驱动、方言怎么处理，留到真正对接时按四个函数填空。
- 硬规则：只读拉取，永不执行 DDL/DML；连接串只能通过 `dsn_env` 引用环境变量，禁止写入 config、sqlite、日志；同步复用 P1 的 `ingest_file` 管线，落成的数据集与上传文件完全同构（同样有 `table_version`、画像、drift 报告）。

### 4.13 多表关系契约（P22）

- `relations` 登记 `(left_dataset, left_col, right_dataset, right_col, kind, confidence, confirmed)`。
- 推断：列名同义匹配 + 类型一致 + 值交集采样（每表随机 1000 行）→ 置信度 0-1，≥ 0.8 自动登记为候选，其余只进 `/relations/suggest`。
- 硬规则：生成的 SQL 里出现的 join 必须命中已登记关系；未登记的 join 一律拒绝，回传「关系未确认」与候选清单。
- 理由：跨表分析是 NL2SQL 线上失败的第一大来源，把 join 条件从「模型猜」改成「查表」。

### 4.14 性能与并发契约（P21）

- 并发模型：所有阻塞工作（DuckDB 查询、pandas、模型 HTTP、子进程）必须经 `app/exec.py:run_blocking()` 调度，`exec_sql` 内部落实这条约定；路由层禁止直接调用阻塞函数。
- 默认 `EXEC_MAX_WORKERS=4`（DuckDB 与 pandas 是 CPU 密集，线程池够；换进程池要序列化结果，默认不做）。
- 目标基线（单机 4 核）：单表 50 万行聚合 p95 ≤ 1.5s；缓存命中 p95 ≤ 100ms；`/ask/stream` 首帧 ≤ 1.2s；10 并发无 5xx 且事件循环心跳延迟 p95 ≤ 200ms。
- 验证方式：`tests/test_p21_perf.py` 同时跑 asyncio 心跳与并发请求，断言心跳延迟与状态码；`bench/bench.py` 输出基线 JSON 存 `bench/baseline.json`，退化即失败。

### 4.15 反馈与配额契约（P24）

- `feedback` 表：`(task_id, verdict, reason, corrected_sql)`；`POST /feedback` 写入，前端在结论卡片上给赞/踩按钮。
- 提升：`POST /feedback/{id}/promote` 把一条 bad 反馈转成 golden 行追加到 `evals/golden.jsonl`（字段按第 4.10 节格式生成），同一问题重复提升只保留最新一条。
- 配额：按「主体 + 日」累计 token 与成本，达到 `QUOTA_DAILY_COST_USD` 即拒绝新的重分析请求并返回 429 + 说明；缓存命中不计入配额。
- 脱敏：反馈只存问题、SQL、结论摘要，不存原始数据行。
- 备注：`# ponytail: 配额记在 sqlite，多实例部署时移到共享存储`

```## 6. 隔离机制

1. 依赖单向：只有 `main.py` 装配；`providers/*` 只被 `registry.py` 惰性 import；`nlu.py` / `agent.py` / `insight.py` 不认识 provider，只接收拼好的 context 或已注册的工具集。
2. 只增不改：每阶段允许改的文件写死在 §5 的「改动范围」；改契约必须在本文件登记并同步更新验收命令。
3. 独立超时与异常捕获：模型、工具、provider 任一失败 → 本次降级，HTTP 仍 200，`degraded` 指明能力与失败类别。
4. 进程与路径隔离：skill 脚本、MCP server、`run_code` 一律子进程，带超时，工作目录限制在项目内。
5. 能力开关（新增能力默认关闭，出问题先关它再验证主链路是否干净）：`ENABLE_SKILLS / ENABLE_KB / ENABLE_MCP / ENABLE_MEMORY / ENABLE_AGENT / ENABLE_SEMANTIC_CACHE / ENABLE_SANDBOX / ENABLE_STREAM / ENABLE_JOBS / ENABLE_AUTH / ENABLE_SOURCES / ENABLE_FEEDBACK / ENABLE_QUOTA`（全部默认 false；唯一例外是 `ENABLE_AGENT`，默认 true，见 §10）。
6. 双壳同源：桌面端只打包同一份后端 + 打开本机回环，不复制业务代码、不开分支。

## 7. 安全边界

- SQL：单条 SELECT、拒 `;`、拒 DDL/DML、read_only、10s、5000 行。
- 上传：后缀白名单（最终 csv/xlsx/xls/pdf/docx；MVP 只开 csv/xlsx/xls，PDF/Word 走 P7/P19）、50MB 上限、xlsx 走 `data_only=True`。
- 代码沙箱：隔离子进程、临时目录、超时、输出上限、import 白名单、`python -I` 不继承环境；明确不是容器级隔离。
- Agent：工具白名单；`write` 类工具需显式开启；步数与单步超时封顶；越权调用记录并拒绝。
- Prompt injection：知识库片段、上传文档、MCP 返回内容一律视为不可信数据，进提示词前包裹标记并剥离指令性内容；文档内容不得触发工具调用或数据导出。
- 认证：单密码 pbkdf2 + HMAC 签名 cookie（HttpOnly、SameSite=Lax、公网强制 Secure）；登录失败限流。
- 数据归属：datasets 带 `owner`，所有读取路径校验。
- 密钥：网页端存本机 `config/local.json`（页面写入、按 profile）或读环境变量；桌面端存 `%APPDATA%`；永不写入 exe、日志、SQL。
- MCP：server 命令只来自 `config/mcp.json`，不接受请求参数；工具白名单；默认只读。
- 日志：不打印文件内容与完整 prompt，只记长度、哈希、模型 id、耗时、成本。
- 数据源：只读账号 + 只读拉取；连接串只经 `dsn_env` 引用环境变量，不落文件与日志；企业库留空位不含凭据与样例数据。
- 反馈：只存问题、SQL 与结论摘要，不存原始数据行。配额：超限直接拒绝，不静默扣费。

## 8. 关键决策（ADR，防止重复讨论同一件事）

- ADR-1 用 DuckDB 而非 SQLite/Postgres：列存聚合快、可直接读 CSV、单文件零部署。
- ADR-2 不引 agent 框架：自写工具调用循环约 100 行，框架会把 50 行变 500 行。
- ADR-3 模型调用集中：`app/llm.py` 唯一出口，业务代码不认识厂商。
- ADR-4 知识库先 FTS5（P7 快），P14 再补向量，两条路并存互为降级。**2026-09-20 落地口径**：FTS5 建在 SQLite 的 `kb_fts`（标准库自带、离线可用；`trigram` 分词才搜得到连续中文，实测 `unicode61` 不行），DuckDB 只管数据集表——它的 `fts` 扩展要联网 `INSTALL`，离线会挂。
- ADR-5 MCP 只做客户端（官方 stdio SDK），不自研协议。
- ADR-6 降级返回 200 而不是 5xx：能力缺失是产品状态，不是服务故障。
- ADR-7 一套后端两种壳：桌面端只打包 + 回环；复制第二份后端是最贵的错。
- ADR-8 只写 `openai_compatible` + `anthropic` 两个适配器：多数厂商给兼容端点，新增厂商只改配置。
- ADR-9 缓存分级：精确键优先、语义兜底；复用结论的前提是数据没变，`table_version` 是这条规则的落点。
- ADR-10 exe 用 PyInstaller onedir + Inno Setup：onefile 冷启动慢、杀软误报多。
- ADR-11 桌面端用用户自带密钥：密钥打进 exe 等于公开泄露。
- ADR-12 复用 SQL 可以，复用结论必须版本一致：结论数字必须对应当前数据。
- ADR-13 用工具调用取代自由文本 SQL：可校验、可白名单、可记账；与 P3 文本路径并存，单跳走便宜那条。
- ADR-14 流式用 SSE 而不是 WebSocket：单向推送足够，FastAPI 原生支持。
- ADR-15 语义检索用现成 embedding 接口 + numpy 暴力检索，不引向量数据库（十万级够用）。
- ADR-16 沙箱用隔离子进程 + 超时，不上容器：单机自用够，公网多租户必须换容器级隔离。
- ADR-17 可观测自建 trace 表，不引 Langfuse：少一个外部依赖，够回答「花了多少钱、慢在哪」。
- ADR-18 评测用 JSONL golden set + 基线对比，不引 eval 框架：pytest 能跑、结果进 git 就能防退化。
- ADR-19 后台作业用 BackgroundTasks + sqlite：单机单进程够用，多实例换 Redis 队列。
- ADR-20 指标口径只在 `config/metrics.json` 定义：Skill 只写方法、引用 metric id，避免同一指标两套公式。
- ADR-21 企业库适配位留空：只定义四个函数的接口、配置与 mock 测试，不预装厂商驱动；成本是一份文档和一个 Protocol，收益是接入时不改主链路。
- ADR-22 join 只走已登记关系：把 join 条件从「模型生成」变成「查表」。
- ADR-23 阻塞工作统一走 `run_blocking`：FastAPI 里直接跑 pandas 或 DuckDB 会卡住事件循环，不许各写各的。
- ADR-24 反馈直接进评测集：用户点踩是最便宜的真实数据来源。
