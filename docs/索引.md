# 文档索引

所有项目文档都在 `docs/` 下，本文件是入口。改代码前先读这里，确认该对着哪份文档施工。

| 文档 | 作用 | 什么时候读 |
|---|---|---|
| 最小可用集-系统设计.md | MVP 的契约与 7 段施工计划（P0/P1/P2/P3/P13/P4/P5） | 现在施工就对着它 |
| 最小可用集-功能说明.md | MVP 能做什么、不能做什么、怎么跑、验收清单 | 想知道第一版范围时 |
| 最小可用集-测试清单.md | MVP 的测试项：成功、反例、手工三层，加横切项与覆盖矩阵 | 每段施工与验收时逐条对照 |
| 系统总体设计.md | 全量 25 段的契约、阶段计划、ADR、验收总表 | 扩展阶段、改契约、查 ADR 时 |
| 系统测试清单.md | 全量 25 段的测试项、12 项专项测试、性能阈值、回归矩阵 | 扩展阶段与上线前自查 |
| 功能介绍与技术栈.md | 全量功能与技术栈，面向使用者与评审 | 写 README、汇报、面试时 |
| 代码台账.md | 已完成文件、已知问题、待开工清单、待推送记录 | 查错、改错、汇报进度时 |

配套文件（在项目根目录）：

- `AGENTS.md` 编码约束，在该目录下工作时自动加载
- `requirements.txt` 依赖清单，每行带 why
- `.gitignore` 忽略规则（数据、数据库、虚拟环境、密钥、打包产物）

阅读顺序：最小可用集-系统设计 → 最小可用集-功能说明 →（要扩展时）系统总体设计 → 功能介绍与技术栈。

阶段编号对照：MVP 直接沿用全量文档的编号，只取了 7 段（P0、P1、P2、P3、P13、P4、P5）；其余阶段不重新编号，按全量文档接在后面，见全量文档第 5、6 节。
