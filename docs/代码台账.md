## 仍然有效的约定（改代码前先看）

| 事项 | 约定 |
|---|---|
| 产品名 | `Knowledge-Analysis-Assistant`；网页端交付（镜像 / compose）；数据在仓库 `data/`（gitignore） |
| 模型与密钥 | 页面可配任意 OpenAI 兼容厂商，写 `config/local.json`；密钥顺序 本地文件 → profile 的 `api_key_env` → `LLM_API_KEY`；调用时读取，保存即生效；`GET/PUT /settings/models` 只回 `id/provider/base_url/model/has_key`，明文不出网关；`PUT` 写盘后把 `default` 设为该 profile |
| 静态挂载 | `web/` 用 `StaticFiles(html=True)` 挂在 `/`，必须排在全部 API 路由之后 |
| `/ask` 两条路径 | `ENABLE_AGENT=true`（默认）走 agent 循环，`false` 回落 P3 单跳；响应形状相同，agent 多一个 `steps` |
| 工具 | 工具签名带 `dataset_id`，由 agent 每步注入，不进给模型的 JSON Schema；白名单、超时、步数预算读 `config/tools.json`，每次调用重读（免重启） |
| 取数与上下文 | 取数按 `/query` 口径 5000 行（末步结果表不再被截到 200 行）；回给模型的超 200 行只回列名与行数（K-008） |
| 数字追溯 | findings 逐条给 `row`（结果表 0 基）即视为整段已追溯；没指认才按字面比对，且先剔掉表名/列名里的数字（K-009/K-018） |
| 结论并入 `/ask` | 只由 `backend/app/api/routes/insight.py` 的 `attach_insight()` 调 `insight.summarize()`（/ask 与 /ask/stream 共用），不动 `agent.run()` 返回值 |
| 修复排期 | A 类（新建文件 / 新路由 / 编排层插调用）随手修；B 类先回设计文档登记再改并同步验收命令；C 类归后续阶段 |
| 路径 | 一律以 `backend/app/core/config.py` 的 `BASE_DIR` 为锚，禁止硬编码绝对路径、禁止依赖 cwd；细则、抽查命令与「换目录跑测试」验收见 `AGENTS.md` §1 路径规则 |
| 前端 | 单文件原生 JS、无构建链；ECharts 走本地 `web/vendor/echarts.min.js`（5.6.1），文件缺失时只出表格不报错 |
| 删除数据集 | `DELETE /datasets/{id}` 清 DuckDB 表 + 原始文件 + 元数据与流水；P20 正式删除/重导入在此基础上扩展 |
| 技能 | 技能 = `skills/`（或项目内任一路径）下带 `SKILL.md` 的子目录；frontmatter 的 `name` 当 slug（缺省用目录名）、`description` 给模型看、`kind` 取 prompt/script、script 还要 `entry`；坏技能单个跳过（`skipped`），不拖垮整批导入 |
| 知识库 | `kb_docs` 存块、`kb_fts`（FTS5 `trigram`，建在 SQLite 而不是 DuckDB：前者标准库自带且离线可用）只负责检索；块上限 500 字符、最多回 5 条命中、片段截 200 字符；查询词短于 3 字符走 LIKE；片段进上下文一律包「不可信」标记并剔掉指令性行 |
| 工具白名单 | 新增能力对应的工具默认进 `config/tools.json` 的 `allow`（模型看得见；能力关掉时给可读拒绝）。不想让模型看见就从 `allow` 删，下一次调用即生效 |
| 技能取用 | prompt 型把 frontmatter 之后的正文给模型（超 4000 字符截断并标 `truncated`，与脚本输出同一上限）；script 型 `subprocess` 跑 `entry`（cwd 锁技能目录、超时 `SKILL_TIMEOUT_S`=20s、输出留末尾 4000 字符）；`enabled: false` 的技能入库但拒绝取用；`use_skill` 按 read 类注册（不写数据） |
