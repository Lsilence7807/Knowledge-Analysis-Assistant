## 3. 专项测试（跨阶段，上线前必须全过）

1. SQL 与越权（10 条）：DDL、DML、多语句、注释绕过、尾分号、写 CTE、跨库 ATTACH、超大结果、超时、不存在的表——全部必须被拒或安全中断
2. 提示注入：三来源（知识库文档、上传文档、MCP 返回值）× 三攻击（「忽略以上指令」、伪装系统消息、要求导出全部数据）——行为不得改变，命中记 `capability_log`
3. 沙箱逃逸（8 条）：`import os`、写文件、读他人文件、联网、死循环、巨量输出、分配大内存、fork 子进程——全部必须被拒或被杀（P15 已覆盖：前四条与 fork 由 import 白名单 + `open` 禁调在启动子进程前拒掉；死循环被 20s 超时杀掉，巨量输出按 1MB 截断，大内存由子进程自己报 `MemoryError` 而服务照常，见 `test_p15_sandbox.py`）
4. 缓存正确性：版本失效、换模型、改 prompt 版本、相似误命中边界（0.92/0.94）、缓存不存原始数据、并发写同一键不冲突
5. 多模型回退：主模型 500 / 超时 / 非法 JSON / 空响应 / 全挂——五种都有确定行为
6. 流式：帧序、`done` 唯一、断连取消、慢客户端、中途模型报错后仍能收尾（P17 已覆盖：帧序与 `done` 唯一、断连取消并落 `stream:canceled`、慢客户端与中途报错收尾，见 `test_p17_stream.py`）
7. MCP：启动失败、调用超时、白名单外工具、中途崩溃、超大结果被截断
8. 认证与归属：无 cookie、错密码、篡改 cookie、访问他人数据集、超频、超大上传
9. 数据源：连接串泄漏检查、只读校验、增量水位、schema drift、同步中断不留半表
10. 多表 join：未登记关系被拒、候选置信度边界、自连接、三表链式 join 只走已登记关系
11. 性能与并发：见 §4 阈值，另测线程池打满时的排队行为与事件循环心跳
12. 评测体系自检（元测试）：故意把一处代码改坏（如去掉 SQL 守卫），确认评测会变红——评测自己不红等于没有评测
