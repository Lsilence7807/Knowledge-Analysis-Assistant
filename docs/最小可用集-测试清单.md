# 最小可用集 · 测试清单

配套：`最小可用集-系统设计.md`（契约与 7 段计划）。设计文档给的是每段一条验收命令；本文件补的是「怎么算测全了」——成功用例、反例用例、手工项、横切项。

约定：所有命令在项目根目录执行，用项目虚拟环境里的解释器：

```
& .\.venv\Scripts\python.exe -m pytest tests/test_p0_skeleton.py -q
```

## 0. 三层结构

| 层 | 含义 | 通不过怎么办 |
|---|---|---|
| 自动（成功） | 正常输入下的预期行为 | 改代码 |
| 反例（负向） | 必须被拒绝或降级的输入，逐条都要被拒 | 改代码；漏一条就算这一步没完 |
| 手工 | 浏览器 / 真实 API Key 下的人工确认 | 记录现象，能修则修，修不了记台账 |

规则：每段开工前先跑一遍全部已完成阶段的自动测试；每段的「反例」清单必须全部命中才算完成。

## 1. 测试数据（`tests/fixtures/`）

| 夹具 | 内容 | 用来测什么 |
|---|---|---|
| dirty.csv | 表头带空格与大写、含 BOM、有重复行、有缺失值、有一列全空、日期格式混杂、金额带千分位与货币符号 | 清洗与画像的每一项都要有对应脏数据 |
| gbk.csv | GBK 编码的中文表头与内容 | 编码识别 |
| sales.xlsx | 两个 sheet，首个正常、第二个为空表 | 多 sheet 取首个 |
| broken.xlsx | 只有公式列、无缓存值 | 空值不崩 |
| big.csv | 50 万行，由脚本生成（不入库） | 性能冒烟与 5000 行截断 |
| empty.csv | 0 行 | 空文件处理 |

落地情况：只有 `dirty.csv` 真的落成文件（P1 与 P5 共用）。其余场景由 `tests/test_p1_ingest.py` 在内存里现造 DataFrame 覆盖，不落文件；`big.csv` 这类压测夹具到 P21 再生成。

## 2. 逐段测试项

### P0 骨架与契约冻结

自动：
- `GET /health` 返回 200 且 body 为 `{"status":"ok"}`
- `GET /capabilities` 返回全部能力键，且值均为 false
- `store.ensure_tables()` 连调两次不报错，表结构不变（幂等）
- 环境变量缺省时 `config` 能给出默认值，不抛异常

反例：
- 未注册路径返回 404
- 未实现的端点返回 404/405，而不是 500

手工：`uvicorn app.main:app --port 8000` 启动无异常堆栈，日志无 traceback

### P1 数据摄入

自动（成功）：
- dirty.csv 清洗后：列名已归一（无空格、统一小写）、类型推断正确、重复行被去掉、缺失率与画像一致
- 返回结构含 `dataset_id/table/rows/cols/profile/clean_log/table_version`，且 `table_version=1`
- gbk.csv 能正确读出中文
- sales.xlsx 只导入首个 sheet，且 `clean_log` 里注明忽略了第二个
- DuckDB 里存在表 `ds_<dataset_id>`，行数与清洗后一致
- 删除数据集：DuckDB 表、上传文件、元数据一起清，删完再查画像返回 404（A 类补丁 K-015）

反例：
- 上传 `.exe` / `.txt` 被拒（后缀白名单）
- 上传超过 `MAX_UPLOAD_MB` 返回 413
- empty.csv 被拒并给出可读错误，不写半个数据集进库
- broken.xlsx 不崩，返回可读说明
- 上传不存在的 dataset_id 查画像返回 404
- 清洗失败的上传（broken.xlsx）不在 `data/files` 留下 `upload_*` 文件（A 类补丁 K-015）

手工：网页上传 dirty.csv 后能看到数据集与画像

### P2 查询与统计层

自动（成功）：
- 正常聚合查询返回 `columns` 与 `rows`，行数与预期一致
- `/stats` 返回描述统计与异常标记，异常行带判定依据

反例（每条都必须被拒，且错误信息可读）：
- `DROP TABLE ds_x`
- `DELETE FROM ds_x` / `UPDATE ds_x SET ...` / `INSERT INTO ...`
- 多语句：`SELECT 1; DROP TABLE ds_x`
- 注释绕过：`SELECT 1 --; DROP TABLE ds_x`
- 尾部带分号：`SELECT 1;`
- 字面量里的符号不算违规：`SELECT 'a;b'`、`SELECT 'it''s;--x'`、`SELECT 1 AS "k;--"` 正常返回；`SELECT 'a;b'; DROP TABLE ds_x` 仍被拒（K-002）
- 写操作 CTE：`WITH x AS (DELETE FROM ds_x) SELECT 1`
- 查询不存在的表 → 可读错误，不是 500
- 结果超 5000 行被截断，且响应里带截断提示
- 查询故意写长（笛卡尔积）在超时后中断，服务仍可用
- 请求体字段缺失或类型错 → 422（K-013；如 `/query` 缺 `sql`、`/stats` 的 `columns` 传字符串）

手工：`/query` 手写一条 SQL 能出表

### P3 自然语言转 SQL

自动（成功）：
- 固定问题在夹具数据上生成 SQL 并执行成功，结果非空
- 返回结构含 `task_id/dataset_id/sql/columns/rows/degraded`

反例：
- 无 API Key 时：返回 200，`degraded` 含 `query:llm`，`sql` 为空，页面仍可用
- mock 让模型返回 `DROP TABLE ds_x` → 被守卫拦住，`degraded` 标记，不执行
- mock 让模型返回非法 JSON → 重试 1 次后降级，不抛 500
- mock 让模型返回超长文本 → 被截断，不写进日志
- 降级时 `tasks` 表仍落一行：`status=degraded`、`degraded_json` 记 `query:llm`（A 类补丁 K-005）
- `/ask` 缺 `question` 或类型错 → 422；`question` 全空白仍 400（K-013）

手工：真实 Key 下问 3 个业务问题，SQL 读起来合理

### P13 Agent 循环与工具调用

自动（成功）：
- 多跳问题「先找环比下降最多的产品，再按渠道拆开」在 2 步内完成，`steps` 长度 ≥ 2
- 单跳问题退化为 1 步
- `agent_steps` 落库条数与 `steps` 一致
- 每步记录 `tool / ok / ms / rows`
- `/ask` 落 `tasks` 一行：带 `session_id`、问题原文、SQL，成功时 `status=ok`（A 类补丁 K-005）
- 每步超时按 `config/tools.json` 的 `timeouts` 生效：`describe_stats` / `detect_anomalies` 不再吃 `exec_sql` 的默认 10s（B 类补丁 K-006）

反例：
- 模型要求调用白名单外工具 → 被拒，写入 `capability_log`，循环继续
- 模型要调不存在的工具名 → 不崩，返回可用说明
- 步数预算耗尽（把 `AGENT_MAX_STEPS` 调到 1 测多跳问题）→ 返回已完成步骤 + 阶段性说明，HTTP 200
- 工具抛异常 → 该步标记失败，不导致 500
- 单步结果 > 200 行 → 只回传摘要与列名，响应体不膨胀

手工：前端步骤面板能看到每步用的工具与耗时

### P4 洞察生成

自动（成功）：
- `Insight` 字段齐全：`summary/findings/anomalies/suggestions/confidence/caveats`
- 结论中的数字能在结果表中找到（数字回溯断言）
- `prior=[]` 时不报错

反例：
- mock 返回缺字段 JSON → 降级：`insight` 为空 + `degraded` 含 `insight:contract`，HTTP 200
- mock 编造结果表里不存在的数字 → 校验器识别并写入 `caveats`（或整体降级）
- 模型不可用时 `/ask` 仍返回 SQL 与结果表
- `/insight` 缺 `sql` → 422，不再是 400 的手工判断（K-013）

手工：结论与表格对得上，没有凭空数字

### P5 前端闭环

自动：
- 首页 200，静态资源可加载
- 首页含删除数据集按钮，且它调到 DELETE 方法（A 类补丁 K-015）
- 全链路：上传 → ask → 断言 `insight` 非空
- `GET /settings/models` 不回传密钥明文；`PUT /settings/models` 新增一个自定义厂商 profile 后 `/ask` 走它且不再降级（模型调用用替身，不真出网）

反例：
- `PUT /settings/models` 缺 id / base_url / model → 400，且不写盘
- 密钥可清空：传空 `api_key` 后该 profile 的 `has_key` 变 false（页面据此演示无密钥降级）

手工清单：
- 脏 CSV 上传后表格列名与类型显示正常
- 多跳提问能出步骤面板
- 图表能切换且数据与表格一致
- SQL 折叠区内容与实际执行一致
- 删掉 API Key 后提问仍显示结果表 + 降级提示
- 在页面填密钥 → 提问出结果表；刷新页面后配置仍在
- 刷新页面后已上传数据集仍在列表里
- 控制台无 JS 报错
- 点「删除数据集」：确认后选项消失、结果区清空，`GET /datasets` 里也没有了（A 类补丁 K-015）

## 3. 横切测试（MVP 就必须有）

- 降级矩阵：模型不可用 / 无密钥 / 工具异常 / 数据集不存在，四种情况都返回 200 且带 `degraded`，不出现 500
- 越权：白名单外工具、白名单外文件后缀，都被拒且留痕
- 幂等：重复上传同名文件不互相覆盖（各自独立 dataset_id）；`ensure_tables` 重复调用安全
- 契约不漂移：所有响应结构用 pydantic 模型断言，字段增删必须是有意的
