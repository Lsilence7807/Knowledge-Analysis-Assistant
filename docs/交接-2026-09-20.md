- **写仓库里已存在的文件需要「完全访问权限」**：沙箱模式（默认）下 `docs/*.md`、`app/*.py`、`.github/*` 一律 `Access denied`，连 `apply_patch` 也一样；新建文件不受影响。本次全程切在完全访问权限下完成。
- **`apply_patch.bat` 不能传多行参数**（cmd 会截断成第一行）。稳定写法：把替换清单写成 Python 脚本，用 `& .\.venv\Scripts\python.exe -` 从 stdin 执行，每处替换先 `assert s.count(old) == 1` 再替换；写文件必须显式 `newline=""`，否则 Windows 会把整份文件的 LF 改成 CRLF（一次性大 diff）。
- **PowerShell 数组展平**：`@( @('old','new') )` 会塌成两个字符串，`$pair[0]` 取到首字符，整份文档会被按字符替换。多组替换一律写 Python。
- **`.cmd` 必须 CRLF**：仓库默认 `* text=auto eol=lf`，LF-only 的批处理里 `goto :label` 会失效，`.gitattributes` 已给 `*.cmd` 开 `eol=crlf`。测 `启动.cmd` 时要把副本放在**仓库根**（脚本用 `%~dp0` 定位项目），放 `%TEMP%` 会在临时目录建 `.venv` 并报找不到 requirements。
- 本机测试要在真实文件系统里跑（K-017）：`pytest tests -q` 在沙箱内 40+ ERROR；CI 上 `tmp_path` 可写，不受影响。
- 起服务前先看端口：`Get-NetTCPConnection -LocalPort 8017 -State Listen`；旧进程占着时新进程会**悄悄退出**，健康检查还通，整轮真链路测的是旧代码。
- 真链路排查用 `curl.exe`（`-s -F "file=@路径"`、`-d '{"json":"…"}'`、`-o NUL -w "%{http_code}"`），别用 `Invoke-RestMethod`。**上传响应的表名字段是 `table`，不是 `table_name`。**
